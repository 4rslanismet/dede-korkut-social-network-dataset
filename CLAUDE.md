# CLAUDE.md — Dede Korkut Narrative Network Project

This file orients future Claude Code sessions working on this repository.

## Project Purpose

A reproducible, multilayer social-network analysis of characters and relations in the
Book of Dede Korkut (a canonical Turkic epic). The project produces: a canonical dataset,
computational analysis, an evidence package, an interactive research portal, and academic
output (paper/thesis skeleton) — all from one shared, auditable pipeline.

## Repository Architecture

```
data/raw/           ← immutable original workbook (XLSX)
data/story_level/   ← immutable per-story legacy CSVs (14 files)
data/final/         ← immutable legacy v3 cleaned dataset
data/processed/     ← canonical rebuild dataset (generated by pipeline)
data/derived/       ← computed story-level metrics (generated)
src/                ← one Python script per pipeline stage
tests/              ← pytest suite
config/             ← analysis.yaml (seed, parameters)
validation/         ← entity review candidates, IAA samples, hashes
outputs/            ← figures, tables, statistics, networks, manifests
reports/            ← one markdown report per project phase
docs/               ← GitHub Pages website (generated + static)
paper/              ← academic paper package (incomplete)
thesis/             ← thesis package (incomplete)
run_pipeline.py     ← master orchestrator
```

## Canonical Data Rules

1. `data/raw/`, `data/final/`, `data/story_level/` are **immutable source data**.
   Never modify them unless genuine corruption is proven.
   Hashes are recorded in `validation/source_baseline_hashes.csv`.

2. `data/processed/` is the **canonical dataset** — generated deterministically by
   `src/build_canonical.py` from `data/final/` and `src/entity_resolution.py`.

3. All analysis reads from `data/processed/`. No script should read `data/final/`
   directly except the canonical-build and provenance-audit stages.

4. Every stochastic parameter lives in `config/analysis.yaml` — never in inline
   literals in source code.

## Protected Directories

Do NOT modify files in these directories without explicit justification:
- `data/raw/`
- `data/final/`
- `data/story_level/`

## Scientific Constraints

- **Weight semantics**: edge weight = tie strength. Shortest-path metrics must use
  distance = 1/strength. Never pass strength directly as path length.
- **No fabricated references**: do not invent citations, DOIs, author names, or
  source-edition details.
- **No unsupported claims**: every headline scientific number must trace to a
  deterministic script and appear in `outputs/results_registry.json`.
- **Entity resolution**: composite-node detection is heuristic. Do not auto-split
  nodes without human review. Candidates go in `validation/`.
- **Null models**: use degree-preserving randomization with BH-FDR correction.
- **Narrative order ≠ chronology**: label all temporal analyses as NARRATIVE ORDER.
- **Source edition provenance**: currently UNRESOLVED. Do not claim otherwise.
- **Inter-annotator agreement**: PENDING HUMAN CODER. Do not fabricate kappa/alpha.

## Reproducibility Commands

```bash
# Full pipeline (analysis + figures + tables + manifest + website + validation)
python run_pipeline.py --all

# Fast mode (100 random graphs instead of 1000 for null models)
python run_pipeline.py --all --fast

# CI mode (validation gate only)
python run_pipeline.py --all --validate-only

# Tests
python -m pytest tests/

# Single stage
python run_pipeline.py --stage <stage_name>
```

## Validation Commands

```bash
python -m pytest tests/                          # unit + integration tests
python run_pipeline.py --stage validate          # schema + referential integrity
python run_pipeline.py --stage validate_site     # website link/asset validation
python src/validate_release_consistency.py       # cross-artifact consistency
```
